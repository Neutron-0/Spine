# SPINE — BATCH 21J CODEX FINDINGS REGISTER
## Master Remediation and Closure Register for Eleventh Independent Deployment Audit Findings

| Finding ID | Title | Severity | Audit State | Batch 21J Status | Remediation Summary & Verification |
|---|---|---|---|---|---|
| **F-01** | Distributed Restore Convergence & Irreversible Global Protocol | **P0** | REOPENED | **CLOSED** | Implemented 6-phase global restore protocol (`PREPARE -> PREPARED -> GLOBAL COMMIT DECISION -> PUBLISH -> VERIFY -> GLOBAL FINALIZE`) across all 7 production participants (`postgres_data`, `spine_storage`, `storage_1_data`, `storage_2_data`, `storage_3_data`, `coordinator_data`, `spine_ssh`). Persisted durable `CommitDecisionRecord` with `.last_valid` journal backup and `safe_atomic_replace`. Once committed, the decision is irreversible: startup recovery rolls forward across all participants to converge on the target generation. Verified via `global_restore_convergence_test.rs` and `production_backup_restore_roundtrip_test.rs`. |
| **F-02** | Correct Restore Phase Semantics & Roll-Forward Startup Recovery | **P0** | REOPENED | **CLOSED** | Completely eliminated treating `StoragePublished` as full restore completion. Refactored `RestorePhase` with discrete participant publication tracking (`Publishing { published_participants }`, `Published`, `Verified`). Pre-decision crashes cleanly abort staging leaving database and live storage untouched; post-decision crashes roll forward without halting indefinitely at `CommitDecision` or `DbPublished`. Verified via `global_restore_convergence_test.rs` and `restore_failure_injection_test.rs`. |
| **F-03** | Canonical Production Participant Contract & Volume Mapping | **P1** | REOPENED | **CLOSED** | Bound all 7 participants to canonical Docker volume names and unique archive paths in `ParticipantRegistry`. Explicitly rejects duplicate participant IDs, duplicate archive paths, unexpected path patterns, and volume substitutions. Verified via `distributed_participant_integrity_test.rs` and `global_restore_convergence_test.rs`. |
| **F-04** | Mandatory Authenticated Encryption for Production Backups | **P1** | REOPENED | **CLOSED** | Enforced fail-closed behavior for backup creation under `core-forge-v1` if passphrase is not supplied. Enforced rejection of plaintext archives during restore unless explicitly permitted via `--allow-unencrypted-legacy-restore` or `SPINE_ALLOW_LEGACY_PLAINTEXT_RESTORE=1`. Full archive protected via streaming SPNEBAK v2 AEAD (AES-256-GCM, PBKDF2 100,000 iterations). Verified via `backup_v2_streaming_test.rs` and `main.rs`. |
| **F-05** | Complete Writer Barriers, Durable Fencing & Atomic Marker Persistence | **P1** | REOPENED | **CLOSED** | Enforced maintenance mode checks and generation monotonicity in `stage_restore`, `commit_restore`, `stage_volume_restore`, and `commit_volume_restore`. Updated `persist_fencing_generation` on coordinator and storage nodes to use `safe_atomic_replace`, sync to disk, and propagate errors immediately, preventing in-memory generation drift on I/O failures. Verified via `distributed_artifact_persistence_test.rs`. |
| **F-06** | Readiness Bound to Exact Logical Identities and Fencing Generations | **P1** | REOPENED | **CLOSED** | Upgraded `/api/v1/health/ready` to query `node_id` from each storage node, verify exact logical identities (`node-1`, `node-2`, `node-3`), reject duplicate endpoints/identities, verify uniform fencing generations across all storage nodes and coordinator, verify database connectivity, storage root, and ensure no active restore journal is in progress. Verified via `routes_health.rs` and `global_restore_convergence_test.rs`. |
| **F-07** | PostgreSQL Credential Model & Configurable Role Names | **P1** | REOPENED | **CLOSED** | Removed raw `DATABASE_URL` and `MIGRATION_DATABASE_URL` credential interpolations from `docker-compose.prod.yml`. Rely on structured connection variables and percent-encoding in `main.rs`. Updated `upgrade_postgres_roles.sh` and `upgrade_postgres_roles.sql` to support configurable `POSTGRES_MIGRATOR_USER` and `POSTGRES_APP_USER` with parameterized psql execution and non-destructive schema privilege checks. |
| **F-08** | Core Forge CI Trust Enforcement Preservation | **P1** | PRESERVED | **CLOSED** | Preserved source-level trust verification, untrusted CI prohibition in Core Forge, and repository/job/run-bound provenance validation. Verified via `profile_enforcement_test.rs` and `hostile_workflow_test.rs`. |
| **F-09** | Release Candidate Artifact Verification & SHA-256 Reconciliation | **P1** | REOPENED | **CLOSED** | Rebuilt all 4 release candidate binaries from current source HEAD. Computed SHA-256 digests in `target/release-candidate/SHA256SUMS` and `RELEASE_CANDIDATE_MANIFEST.md`. Documented SBOM tooling requirements (cargo-cyclonedx / cargo-sbom not pre-installed on platform). |
