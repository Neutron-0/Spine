# SPINE — BATCH 21G CODEX FINDINGS REGISTER
## Remediation and Closure Register for Eighth Independent Deployment Audit Findings

| Finding ID | Title | Severity | Audit State | Batch 21G Status | Remediation Summary & Verification |
|---|---|---|---|---|---|
| **F-01** | Mandatory Production Backup Participant Completeness | **P0** | REOPENED | **CLOSED** | Under `core-forge-v1`, `ParticipantRegistry::validate_participants` strictly forbids incomplete cluster backups at both backup and restore time. All 7 authoritative persistent resources (`postgres_data`, `spine_storage`, `storage_1_data`, `storage_2_data`, `storage_3_data`, `coordinator_data`, `spine_ssh`) must be present, non-zero length, valid SHA-256, and with matching fencing generation. Missing participants fail closed immediately with `FATAL BACKUP INCOMPLETE`. Verified via `distributed_participant_integrity_test.rs` (`test_participant_registry_production_enforcement`). |
| **F-02** | SSH Host Key Identity Preservation & Cryptographic Verification | **P0** | REOPENED | **CLOSED** | Authoritative host keypair (`host_key_ed25519` and `.pub`) is resolved via `SSH_DIR` / `storage_root/ssh` and packaged into `ssh/ssh_identity_snapshot.tar.gz` inside the encrypted SPNEBAK v2 archive. Host fingerprint is recorded in `manifest.json`. Restore verifies OpenSSH private key parsing and matches SHA-256 fingerprint, strictly failing closed on tampering. Verified via `distributed_participant_integrity_test.rs` (`test_ssh_host_identity_capture_and_restore_roundtrip`). |
| **F-03** | 6-Phase Distributed Cutover & Retained Rollback Generations | **P0** | REOPENED | **CLOSED** | Implemented 6-phase distributed cutover protocol (`PREPARE` -> `PREPARED` -> `COMMIT DECISION` -> `PUBLISH` -> `VERIFY` -> `FINALIZE`). Storage nodes retain `.old_restore_<id>`, coordinator retains `previous_committed_state`, and API storage retains `.old_generation_<id>` throughout publication and verification. If any participant fails post-cutover verification, distributed rollback reverts all nodes to previous generations. Old generations are purged only during Phase 6 (`FINALIZE`). Verified via `restore_failure_injection_test.rs` and `distributed_participant_integrity_test.rs` (`test_distributed_cutover_multi_phase_rollback_preservation`). |
| **F-04** | Monotonic Persistent Fencing Tokens Across Process Restarts | **P0** | REOPENED | **CLOSED** | Storage nodes persist `.fencing_generation` and coordinator persists `.coordinator_fencing_generation` atomically on disk. Node initialization loads persisted generation; corrupt records fail closed; generations advance monotonically and never regress upon restart. Verified via `distributed_artifact_persistence_test.rs` (`test_fencing_generation_persistence_and_restore_finalization`) and `restore_failure_injection_test.rs`. |
| **F-05** | Transactional Restore Generation Token & Fail-Closed Startup | **P0** | CLOSED | **VERIFIED** | `_restore_generation` token is written within the exact database restoration transaction before commit. Startup recovery verifies generation token consistency between database and filesystem storage, failing closed on mismatch. Verified via `restore_failure_injection_test.rs`. |
| **F-06** | PostgreSQL 01-init-roles.sh Safe Dynamic Quoting | **P1** | REOPENED | **CLOSED** | Completely eliminated dollar-quoted string variable expansion bugs in `docker/postgres/01-init-roles.sh`. Replaced with `SELECT format(...) \gexec` using safe `%I` identifier quoting and `%L` literal quoting. All administrator password fallbacks removed (`${POSTGRES_ADMIN_PASSWORD:?required}`). Verified via shell script syntax inspection and test database initialization. |
| **F-07** | Special Character Database Credential Percent-Encoding | **P1** | REOPENED | **CLOSED** | Replaced raw string interpolation of database connection URLs in `spine-api` with `url::Url` percent-encoding. Special reserved URL characters (`:`, `@`, `/`, `#`, `?`, `%`) in passwords or usernames are correctly encoded into standard PostgreSQL connection URIs. Verified via `resolve_postgres_url` unit testing and CLI integration. |
| **F-08** | Production Ingress Isolation & Direct Port Removal | **P1** | CLOSED | **VERIFIED** | Direct host port publications for internal services (`postgres`, `spine-api`, `storage-nodes`, `coordinator`) remain removed in `docker-compose.prod.yml`. Ingress gateway (`spine-ingress-proxy`) terminates TLS on port 443 with mandatory HTTP -> HTTPS redirection. `spine-frontend` isolated from public networks. Verified via compose YAML inspection. |
| **F-09** | Production Container Hardening & Least Privilege | **P1** | REOPENED | **CLOSED** | Added container hardening to all services in `docker-compose.prod.yml`: `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`, `read_only: true`, memory-limited tmpfs mounts (`/tmp`), and non-root execution (UID 10001). Runtime database connections use unprivileged `spine_app` role with DDL privileges revoked. Verified via compose YAML inspection. |
| **F-10** | Untrusted Workflow Trigger Disallowance in Core Forge | **P1** | CLOSED | **VERIFIED** | Under `core-forge-v1`, untrusted triggers, fork PR workflows, and non-authoritative runner registrations are strictly forbidden. Authoritative database trust tokens are required for all job claims and completions. Verified via `hostile_workflow_test.rs` and `profile_enforcement_test.rs`. |
| **F-11** | Disposable Test Database Safety Contract | **P1** | CLOSED | **VERIFIED** | Destructive test operations strictly gated behind `SPINE_ALLOW_DESTRUCTIVE_TESTS=1`. Prohibited silent fallback from app pool to migrator pool. Verified via `test_database_safety_test.rs`. |
| **F-12** | Release Candidate Artifacts & Checksum Registry | **P1** | REOPENED | **CLOSED** | Recompiled all 4 release candidate binaries (`spine.exe`, `spine-coordinator.exe`, `spine-storage-node.exe`, `spine-api.exe`) from final source tree. Calculated exact SHA-256 sums and updated `target/release-candidate/SHA256SUMS` and `RELEASE_CANDIDATE_MANIFEST.md`. All workspace test suites executed with 100% pass rate. |
