# SPINE — BATCH 21F CODEX FINDINGS REGISTER
## Remediation and Closure Register for Seventh Independent Deployment Audit Findings

| Finding ID | Title | Severity | Audit State | Batch 21F Status | Remediation Summary & Verification |
|---|---|---|---|---|---|
| **F-01** | Multi-Volume Deployment-Wide Backup Architecture | **P0** | REOPENED | **CLOSED** | Expanded backup and restore scope from single storage root to all 7 authoritative persistent resources: `postgres_data`, `spine_storage`, `storage_1_data`, `storage_2_data`, `storage_3_data`, `coordinator_data`, and `spine_ssh`. Added `VolumeSnapshotManifest` and snapshot/restore RPCs in `spine-cluster`. Multi-volume coordinator client coordinates snapshot capture across storage nodes and coordinator, packing all snapshots into `SPNEBAK v2` archive. Data inventory formalized in `docs/DATA_INVENTORY.md`. Verified via `restore_failure_injection_test.rs` and `spine-cluster` test suite. |
| **F-02** | System-Wide Monotonic Fencing Barrier & Storage Guards | **P0** | REOPENED | **CLOSED** | Extended global writer barrier with monotonic 64-bit generation tokens (`fencing_generation`) tracked in `_cluster_maintenance_barrier` and PostgreSQL advisory lock `0x5350494E_4542414B`. Storage node backend (`FileSystemStorageBackend`) and coordinator store (`FileBackedCoordinatorStore`) enforce maintenance barrier and reject mutations/commits (`StaleFencingGeneration` / `InMaintenanceBarrier`). Verified via `restore_failure_injection_test.rs` (`test_storage_node_fencing_rejects_stale_generation`) and `spine-cluster` tests. |
| **F-03** | Whole-Generation Atomic Restore & Staging Replacement | **P0** | REOPENED | **CLOSED** | Replaced file-by-file overlay restore with atomic whole-generation directory replacement. Staging directory extracts new generation completely. During `publish_storage`, live tree is atomically moved to `.old_generation_<id>` before staged files are published. Absent files from older generations are completely eliminated. In case of failure, atomic rollback restores `.old_generation_<id>`. Verified via `restore_failure_injection_test.rs` (`test_whole_generation_cutover_eliminates_absent_files`). |
| **F-04** | Fail-Closed Crash Recovery & Transactional Generation Token | **P0** | REOPENED | **CLOSED** | Inserted `_restore_generation` recording *inside active restore transaction before commit*. Upgraded `handle_startup_recovery` to fail closed if catalog query fails, if tables exist without `_restore_generation`, or on generation mismatch between database and storage. Verified via `restore_failure_injection_test.rs` (`test_startup_recovery_fails_closed_on_interrupted_db_cutover`, `test_startup_recovery_fails_closed_on_generation_mismatch`). |
| **F-05** | Authoritative Trust-Token Binding in Execution Path | **P1** | REOPENED | **CLOSED** | Enforced authoritative database trust token resolution in production runner paths (`acquire_job` and `complete_job`). Removed empty repository ID bypass in `IsolatedRunnerExecutor`. Token strictly bound to `run_id`, `job_id`, `repository_id`, and fork classification. Verified via `hostile_workflow_test.rs` and `profile_enforcement_test.rs`. |
| **F-06** | Production PostgreSQL Roles & Secret Quoting | **P1** | REOPENED | **CLOSED** | Enforced distinct passwords for `spine_admin`, `spine_migrator`, and `spine_app` without fallbacks in `docker/postgres/01-init-roles.sh`. Used safe `format('%I', '%L')` SQL quoting and non-destructive `has_schema_privilege` probe in `scripts/upgrade_postgres_roles.sh`. Runtime role `spine_app` granted DML only; `CREATE` on schema `public` revoked. Verified via static code review and shell script syntax validation. |
| **F-07** | Production Compose Network & Container Security | **P1** | REOPENED | **CLOSED** | Hardened `docker-compose.prod.yml`: added `security_opt: [no-new-privileges:true]` across all services, distinct secret files for postgres roles, non-root user execution (UID 10001), healthcheck via `spine_app`, and removed direct public network access from database and internal cluster services. Verified via compose YAML inspection. |
| **F-08** | Disposable Test Database Safety Contract | **P1** | REOPENED | **CLOSED** | Enforced strict `SPINE_ALLOW_DESTRUCTIVE_TESTS=1` gating in `test_database_safety_test.rs`. Prohibited silent fallback from `app_pool` to `migrator_pool`. Runtime test connections connect strictly as unprivileged `spine_app`. Verified via `test_database_safety_test.rs`. |
| **F-09** | Release Candidate Artifacts & Reproducible Verification | **P1** | OPEN | **CLOSED** | Built release binaries for all 4 targets (`spine.exe`, `spine-coordinator.exe`, `spine-storage-node.exe`, `spine-api.exe`) under optimized release profile. Generated exact SHA-256 checksums in `target/release-candidate/SHA256SUMS` and `RELEASE_CANDIDATE_MANIFEST.md`. Executed full test suites with 100% pass rate. Verified via reproducible test runs. |
