# SPINE — BATCH 21E CODEX FINDINGS REGISTER
## Remediation and Closure Register for Sixth Independent Deployment Audit Findings

| Finding ID | Title | Severity | Audit State | Batch 21E Status | Remediation Summary & Verification |
|---|---|---|---|---|---|
| **F-01** | System-Wide Global Writer Coordination & Data Inventory | **P0** | REOPENED | **CLOSED** | Extended global writer barrier across all services mutating persistent state. Wired `acquire_write_permit()` and `verify_active()` to runner endpoints (`register_runner`, `heartbeat`, `acquire_job`, `ingest_logs`, `complete_job`). Established authoritative data inventory covering `postgres_data`, `spine_storage`, `storage_1_data`, `storage_2_data`, `storage_3_data`, `coordinator_data`, and `spine_ssh` in `docs/DATA_INVENTORY.md`. Verified via `cross_process_coordination_test.rs` and compilation tests. |
| **F-02** | Crash-Recoverable Restore State Machine & Generation Alignment | **P0** | REOPENED | **CLOSED** | Fixed split-brain restore hazard by embedding generation tokens across resources (`_restore_generation` table in PostgreSQL and `.spine_storage_generation` in storage root). Formal durable state machine with phases: `Initialized` -> `StagedStorage` -> `StagedDb` -> `DbPublished` -> `StoragePublished` -> `Committed`. On startup, `handle_startup_recovery` fails closed on incomplete restore or generation mismatch. Verified via `restore_failure_injection_test.rs`. |
| **F-03** | Workflow Trust-Token Construction & Provenance Binding | **P1** | REOPENED | **CLOSED** | Removed public `AuthoritativeTrustToken::for_test` constructor from production builds, gating it strictly behind `#[cfg(any(test, feature = "test-support"))]`. Bound token strictly to `run_id`, `job_id`, `repository_id`, `is_fork`, and `trust_classification`. Enforced run and repository identity validation and fork untrusted classification. Verified via `hostile_workflow_test.rs` and `profile_enforcement_test.rs`. |
| **F-04** | PostgreSQL Provisioning & Dynamic Role Parameterization | **P1** | REOPENED | **CLOSED** | Removed hardcoded credentials and database names from `docker/postgres/init-roles.sql`. Implemented parameterized dynamic role provisioning entrypoint `docker/postgres/01-init-roles.sh` with Docker secret file support (`POSTGRES_*_PASSWORD_FILE`). Preserved strict least privilege: `spine_admin`, `spine_migrator` (DDL owner), `spine_app` (runtime DML only, `REVOKE CREATE ON SCHEMA public`). Verified via `postgres_least_privilege_test.rs`. |
| **F-05** | Production Compose Network Hardening & Container Boundary | **P1** | REOPENED | **CLOSED** | Removed `spine-public` network from `spine-frontend` in `docker-compose.yml`. Frontend belongs strictly to `spine-ingress-proxy`, routing all web traffic through `ingress` TLS reverse proxy. Maintained container security boundaries with non-root runtime users and capability restrictions. |
| **F-06** | Fail-Closed Startup Recovery & Split-Brain Prevention | **P0** | REOPENED | **CLOSED** | Replaced silent warning in server startup with strict fail-closed enforcement: if an incomplete restore cutover (`DbPublished`, `StoragePublished`, `Failed`) or generation mismatch is detected, server startup aborts immediately with a fatal exit code. Verified via `restore_failure_injection_test.rs`. |
| **F-07** | Disposable Test Database Harness Identity Fallback Removal | **P1** | REOPENED | **CLOSED** | Removed silent fallback in `tests/common/mod.rs` where `app_pool` fell back to `migrator_pool` on failure. Authentication as `spine_app` must succeed directly or fail closed. Verified via `postgres_least_privilege_test.rs` and `test_database_safety_test.rs`. |
