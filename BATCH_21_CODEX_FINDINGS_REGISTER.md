# SPINE — BATCH 21D CODEX FINDINGS REGISTER
## Remediation and Closure Register for Independent Deployment Audit Findings

| Finding ID | Title | Severity | Audit State | Batch 21D Status | Remediation Summary & Verification |
|---|---|---|---|---|---|
| **F-01** | Database Snapshot & Global Writer Coordination | **P0** | REOPENED | **CLOSED** | Replaced process-local barrier with cluster-wide PostgreSQL session advisory lock (`0x5350494E_4542414B`). Dedicated non-pooled `PgConnection` instances guarantee immediate kernel-level lock cleanup on synchronous `Drop` without async detached tasks. Fully wired across all mutating HTTP routes, Git transports, and background workers (`ProvisioningWorker`, `WorkflowScheduler`, `WebhookOutboxWorker`). Enforced 16 MiB line bound on streaming dumps. Verified via `cross_process_coordination_test.rs`. |
| **F-02** | SPNEBAK v2 Restore & Bounded Archive Processing | **P1** | REOPENED | **CLOSED** | Implemented two-phase staged restore state machine with durable `.spine_restore_journal.json`. Storage is isolated in `.tmp_restore_<uuid>` and never published until database restore succeeds. Unbounded memory allocations removed from legacy v1 rotation (bounded read with `MAX_LEGACY_V1_ARCHIVE_BYTES` = 64 MiB). Enforced limits: `MAX_MANIFEST_BYTES` (16 MiB), `MAX_ARCHIVE_FILE_COUNT` (1,000,000), `MAX_ARCHIVE_PATH_LEN` (4096 bytes). Verified via `restore_failure_injection_test.rs`. |
| **F-03** | Workflow Provenance at Executor Boundary | **P1** | PARTIAL | **CLOSED** | Hardened `IsolatedRunnerExecutor::execute_job` to require an `AuthoritativeTrustToken` loaded directly from the database record of the workflow run. Callers can no longer pass raw booleans or assert trust. Test harness factory `AuthoritativeTrustToken::for_test` restricted to integration test scopes. Verified via `hostile_workflow_test.rs`, `profile_enforcement_test.rs`, and `workflow_ci_e2e_test.rs`. |
| **F-04** | PostgreSQL Exposure & Role Least Privilege | **P1** | PARTIAL | **CLOSED** | Established three distinct identities: `spine_admin` (bootstrap administrator/superuser), `spine_migrator` (DDL owner of database and public schema), and `spine_app` (runtime DML only: SELECT, INSERT, UPDATE, DELETE on tables; USAGE, SELECT, UPDATE on sequences; `REVOKE CREATE ON SCHEMA public FROM spine_app`). Added `docker/postgres/init-roles.sql`, `scripts/upgrade_postgres_roles.sql`, and `scripts/upgrade_postgres_roles.sh`. Verified via `postgres_least_privilege_test.rs`. |
| **F-05** | Production Toolchain MSRV Alignment & Network Hardening | **P1** | OPEN | **CLOSED** | Aligned all Dockerfiles (`Dockerfile.production`, `git-alternative/Dockerfile.coordinator`, `git-alternative/Dockerfile.storage-node`, `github-alternative/backend/Dockerfile.api`) to MSRV `rust:1.88-bookworm`. Multi-network architecture enforces strict segregation: `spine-internal` (no internet/ingress), `spine-ingress-proxy` (internal routing), and `spine-public` (edge HTTPS 80/443 and SSH 2222 only). |
| **F-06** | Credential-Bearing CLI Arguments & Recoverable Restore | **P1** | REOPENED | **CLOSED** | Eliminated credential-bearing CLI flags (`--database-url`, `--target-database-url`, `--migration-database-url`) from all CLI entrypoints (`spine-api serve`, `migrate`, `bootstrap-admin`, `backup create`, `backup restore`). Credentials must be supplied via `--*-file` flags or environment variables. Staged restore ensures target storage is completely untouched if database restore fails. Automatic crash recovery cleans up interrupted staging on subsequent server startup. |
| **F-07** | Migration Lock Cancellation & Advisory Lock Verification | **P1** | CLOSED | **CLOSED** | Preserved transaction-level advisory locks for database migrations. Database-scoped lock query in `advisory_lock_test.rs` prevents cross-database test collision. Verified cancellation, exclusion, and recovery under parallel execution. |
